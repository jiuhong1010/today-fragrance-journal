# 今日用香志｜内容包 v1

本目录是 MVP 0.1 的第一批内容生产物，可直接作为 Luna 的静态数据输入夹具。

当前状态：**可导入开发、不可直接发布**。

原因：50 款香水和 30 组叠香已按产品方案完成结构化初稿，但每条记录仍需补齐品牌官方来源 URL、查询日期、事实审校和实际试喷记录。`contentStatus: draft` 或 `sourceStatus: pending-official-review` 的内容不得进入正式发布构建。

## 文件

- `perfumes.v1.json`：50 款香水资料初稿。
- `layering.v1.json`：30 组叠香白名单初稿。
- `perfumes.v1.js`、`layering.v1.js`：微信小程序运行时加载的静态 JS 镜像；内容修改后需要同步生成。
- `perfume-images.v1.js`：50 款内置香水的本地图片索引、资源版本与开发阶段来源记录。
- `manifest.v1.json`：数量、配额和发布门槛。

## 数量与配额

- 香水：50 条。
- 叠香：30 条。
- 香水主家族：清新 15、花香 13、琥珀 10、木质 12。
- 叠香类型：清新+木质 8、柑橘/绿意+花香 6、花香+木质 5、花香+琥珀 4、果香+干燥木质/芳香草本 4、水生+芳香草本/木质 3。
- 叠香引用的香水 ID 必须全部存在于 `perfumes.v1.json`。
- 同一香水最多出现在 3 组叠香中。

## 内容审校顺序

1. 核对品牌、产品名、浓度版本和官方公开香材。
2. 为每条补齐官方 URL、查询日期和审校人。
3. 把 50 张开发阶段目录图替换为品牌授权素材，逐张复核瓶型、浓度和版本。
4. 核对 14 家族归类、浓淡、扩散、温度、场合和气质标签；这些是产品编辑判断，不能写成品牌事实。
5. 删除或改写复制品牌宣传语的句子。
6. 叠香完成低剂量、分区试喷；记录至少 3 位体验者的反馈。
7. 双人审校后将记录改为 `contentStatus: publishable`。

## 导入约束

正式构建必须拒绝以下情况：

- 香水数量不等于 50。
- 香水本地图片数量不等于 50，或图片状态不是 `brand-authorized-reviewed`。
- 叠香数量不等于 30。
- ID 重复或叠香引用悬空 ID。
- 必填字段缺失。
- 内容状态不是 `publishable`。
- 来源状态不是 `official-reviewed`。
- 叠香主香和辅香相同。
- 同一香水参与叠香超过 3 组。

## 给 Luna 的说明

开发阶段可以使用当前 `draft` 数据验证页面、推荐算法、无候选状态和叠香白名单匹配。页面不得把 `sourceStatus` 或草稿内容状态展示给最终用户；发布构建必须在导入前运行 manifest 校验并阻断不合格内容。
